# Replay Lab — переход к локальной разработке

Это снимок исходников опубликованной версии 16. Исходный commit: `20a5f7634ce14a6b9af3cfbb219bffc5faa4faae` от 12 октября 2026 года. Архив подготовлен 15 октября 2026 года.

Сайт: https://nq-es-replay-lab.rick-sunches.chatgpt.site

## Что сделать владельцу

1. Распакуйте ZIP в постоянную папку, например `Projects/Replay-Lab`. Работайте с распакованной папкой, в которой лежит `package.json`.
2. Установите Node.js 24 или новее. Текущий проект проверялся на Node 24.19.0. Проверьте в терминале: `node --version` и `npm --version`.
3. Откройте папку в VS Code и установите официальное расширение Codex от OpenAI, затем войдите в свой аккаунт ChatGPT. Можно также открыть эту папку как локальный проект в настольном приложении ChatGPT и выбрать Codex.
4. Перед переносом сессий откройте опубликованный сайт и нажмите «Резервная копия» в левой панели. Сохраните JSON рядом с проектом, но не добавляйте личные данные в публичный Git-репозиторий.
5. Передайте Codex задание ниже. После реализации локального режима он должен сообщить точную команду запуска и адрес localhost.
6. Для истории изменений создайте отдельный локальный Git-репозиторий; затем при желании подключите свой приватный GitHub. Этот ZIP не содержит каталога `.git` и прежней истории коммитов.

Официальная инструкция Codex: https://learn.chatgpt.com/docs/ide

## Готовое первое задание для Codex

> Прочитай LOCAL-SETUP.md и код Replay Lab. Подготовь эту копию для полноценного локального запуска через `npm run dev`. Используй существующие фронтенд, торговый движок и API. Добавь локальные адаптеры SQLite и файлового хранилища вместо Sites D1/R2, постоянное сохранение сессий и изображений и выдачу имеющихся месячных котировок из market-archives/. Локальный сервер должен слушать только 127.0.0.1; фиксированная локальная личность допустима только в этом режиме. Не меняй защиту производственного API. Сохрани формат резервных копий, данные, цены и временные метки. Проверь создание и восстановление парной NQ/ES-сессии, независимые прокрутку и масштаб графиков, общее время replay, импорт JSON, CSV и изображений, а также сохранение после перезапуска. Создай локальный Git-репозиторий, если его ещё нет. Обнови инструкцию запуска под мою ОС. Работай только с этой локальной копией, без публикации и изменения размещённого сайта. Не объявляй перенос личных файлов завершённым, пока они не проверены.

## Важное о текущем запуске

В исходном `package.json` есть только `build` и `test`; команды `dev` пока нет. Простое открытие `dist/index.html` или раздача статической папки не заменяет сервер: сохранения, CSV и изображения обращаются к `/api/*`. `npm run build` собирает Cloudflare Worker для Sites, а не запускает локальный сайт. Требуется один раз добавить локальный режим — это и есть первое задание выше.

В исходной версии нет внешних npm-зависимостей, поэтому для существующих проверок `npm install` не нужен:

```sh
npm test
```

Команда использует встроенные возможности Node, включая `node:sqlite`, проверяет исходники, собирает Worker и проверяет собранный API. При добавлении зависимостей локальным Codex порядок установки может измениться. Исходники ZIP не изменялись; 45 автоматических проверок были успешно выполнены перед публикацией этой версии. При подготовке ZIP отдельно проверены полнота снимка и контрольные суммы всех 88 месячных файлов котировок. Визуальная проверка браузером здесь не выполнялась.

## Что находится в архиве

- `dist/` — редактируемые исходники интерфейса, графиков и торгового движка. Это НЕ одноразовая папка сборки: нельзя удалять её командой clean.
- `worker/api.mjs` — серверный API. В размещённом сайте использует `DB` и `BUCKET`.
- `drizzle/` — SQL-миграции.
- `market-archives/` — 88 исходных месячных файлов `.b64`: gzip, закодированный base64. Это реальные имеющиеся котировки, включая старые версии для восстановления сессий. Контрольные суммы и каталоги находятся в `dist/market-archives.mjs`.
- `market-archives/evidence/` — сведения о восстановлении пропусков NQ за октябрь 2025.
- `tests/` и `scripts/` — проверки, сборка и воспроизводимость данных.
- `.openai/hosting.json` — идентификатор существующего сайта и имена серверных ресурсов. Это конфигурация хостинга, а не доступ к базе или облачным файлам.
- `EXPORT-INFO.json` — commit и SHA-256 каждого файла исходного снимка.

В ZIP нет токенов доступа Sites, каталога `.git`, `node_modules`, выгрузки личной базы или сформированного Worker. Последний воспроизводится командой сборки.

## Что не переносится вместе с исходниками

1. JSON «Резервная копия» содержит сессии, сделки, заметки и стратегии. Это НЕ полный экспорт всех облачных объектов. Восстановление сессий на штатных встроенных и curated-архивах возможно после настройки локального чтения имеющихся данных.
2. Лично импортированные CSV и изображения журнала хранятся отдельными объектами в облаке. Их содержимого нет ни в этом ZIP, ни в JSON: потребуются отдельное скачивание в авторизованной сессии и перенос с сохранением/перепривязкой ID. При отсутствии полного экспорта сохраняйте доступ к прежнему сайту. Повторный импорт CSV с новыми ID сам по себе не восстановит ссылки старых сессий.
3. Настройки, которые остались только в localStorage прежнего браузера, автоматически не переедут: у localhost другой origin. В частности, проверьте настройки графика и темы.
4. Чат с историей разработки не является частью ZIP. Ключевой технический контекст и принятые требования собраны ниже.

## Контекст для продолжения работы

- Replay Lab — ручной бэктестинг фьючерсов NQ и ES. Название сессии и остальные настройки видны сразу; NQ и ES по умолчанию выбраны вместе. Главная — сессии без превью графика.
- Во время теста NQ и ES показаны рядом. Replay-clock и перекрестие связаны; прокрутка, позиция и масштаб каждого графика независимы. Дополнительный график по умолчанию наследует таймфрейм главного, доступен собственный таймфрейм и разворот рабочей области.
- Есть сессии с восстановлением, Market/Limit/Stop, частичные выходы, SL/TP, BE, стратегии, журнал с заметками/тегами/изображениями/правилами и аналитика. Торговый движок ведёт основной инструмент; второй график служит для анализа.
- Светлая/тёмная тема, настройки свечей/цветов/шкал/таймзоны/сессий и индикаторов. Это TradingView Lightweight Charts с собственным интерфейсом. Импорта раскладок аккаунта TradingView, Pine Script и полного паритета с TradeZella нет.
- Модель исполнения — минутный OHLC, следующий доступный бар, комиссии и проскальзывание; при неоднозначном порядке касания SL/TP приоритет у SL. Будущие свечи скрыты на обоих графиках.
- Основной NQ: `curated-NQ-history-2024-2026-v2`, 820906 свечей, по 4 мая 2026. Основной ES: `curated-ES-history-2024-2026`, 788286 свечей, по 10 июня 2026. Отдельные недавние серии: 9 сентября — 7 октября 2026. Между архивами остаются пробелы 2026; полного непрерывного 2026 года нет. Смотрите точные временные метки и пробелы в каталоге.
- Старый NQ-архив сохранён для точного восстановления сессий. Дополнительная скорректированная серия Kaggle отделена от исходных цен. Не склеивайте их, не меняйте ID архивов/свечей и не создавайте искусственные свечи для заполнения дыр.
- HF Market Data отключён владельцем источника 2 октября 2026; старый API не способ восстановить недостающую историю. Новые платные источники и покупки не подключались.
- Размещение в Sites использует доверенный заголовок `oai-authenticated-user-id`, D1 и R2. Без соответствующей среды текущий Worker не предоставляет локальные личные данные автоматически. Не подставляйте секреты прежнего сайта в клиентский код.
- Прежний сайт остаётся приватным. В этом переходе его код и права доступа не менялись. Любая дальнейшая публикация — отдельная задача владельца.

## Минимальная проверка переноса

После реализации `npm run dev` создать сессию NQ+ES на январе 2024, раскрыть несколько свечей, проверить отсутствие будущих цен и независимость панорамирования. Провести сделку, добавить заметку/изображение, перезапустить сервер и браузер: данные должны восстановиться. Затем проверить выбранный период 2025, импорт резервной копии и все связанные с ней источники и изображения. Проверки должны проходить без записи в производственные данные Sites.
